# M4 备忘：本地 DP 在这个数据规模下要花多少精度

**日期**：2026-10-25
**数据**：MIT-Stanford，135 颗电池（115 训练 / 20 测试），2700 行 × 1003 列特征
**设置**：100 轮、`local_epochs=3`、Adam 1e-3、`batch_size=64`、标签中心化到 1.0
**规模**：5 个 noise 档 × 8 seeds = 40 个 run，全部 `results/fedavg__iid__le3__nm*__seed*.json`

---

## 1. 结论摘要

H4 原文是两半：「精度代价随噪声单调上升」**且**「在 ε ≤ 8 时仍可用」。
这两半在本数据上给出**不同**的答案，必须分开报。

| nm | MAE (mean±std) | seed 波动 | ε (δ=1e-5) | vs `nm=0` 机制对照 | vs 非 DP 同预算 |
|---|---|---|---|---|---|
| 0（机制对照） | 0.01621 ± 0.00189 | 11.7% | ∞ | — | +39.2%（p_t=0.0945，不显著） |
| 1 | 0.02947 ± 0.00408 | 13.9% | 152.31 | **+81.8%**（8/8 同向） | +153.0% |
| 2 | 0.03475 ± 0.00468 | 13.5% | 49.11 | **+114.3%**（8/8 同向） | +198.3% |
| 4 | 0.04066 ± 0.00534 | 13.1% | 18.65 | **+150.8%**（8/8 同向） | +249.0% |
| **8** | 0.04643 ± 0.00603 | 13.0% | **7.84** | **+186.3%**（8/8 同向） | **+298.5%** |

参照：非 DP FedAvg le=3 = 0.01165 ± 0.00777；C0 中心化 = 0.00157；
C1 本地独立 = 0.03446；常数预测器（输出中心化后的 1.0）= **0.00350**。

**判定**：

1. **单调性：支持。** MAE 随 nm 严格递增，四档 DP 臂相对机制对照 8/8 同向、
   全部显著（p_sign=0.0078 是 n=8 的下限）。噪声确实按预期在伤精度。
2. **ε ≤ 8 时仍可用：推翻。** 唯一达标的 nm=8（ε=7.84）相对机制对照劣化
   **+186.3%**、相对非 DP 同预算劣化 **+298.5%**，远超 §11.3 的 30% 阈值。
3. **DOD ① 的字面条款「noise=1.0 处 ε ≤ 8」结构上不可达**（见 §2）。

## 2. ε 不是自由变量：为什么 nm=1 换不来 ε ≤ 8

扫 nm **之前**先跑 `scripts/check_dp_budget.py --config configs/dp.toml`：

| nm | ε | 达到 ε ≤ 8？ | 噪声 Std（批均值梯度上） |
|---|---|---|---|
| 0（对照） | ∞ | 不是 DP 臂 | 0 |
| 1 | 152.31 | 否 | 0.0250 |
| 2 | 49.11 | 否 | 0.0500 |
| 4 | 18.65 | 否 | 0.1000 |
| **8** | **7.84** | **是** | **0.2000** |

推导（plan §7.1）：

    q     = 1 / ceil(每客户端行数 / batch_size) = 1 / ceil(80/64) = 0.5
    步数  = num_rounds × local_epochs × 每 epoch 批次数 = 100 × 3 × 2 = 600
    ε     = RDP(q, nm, 步数) at δ=1e-5

**q=0.5 意味着 subsampling 几乎没有放大作用**——Poisson 抽样的隐私放大只在小
抽样率下显著。于是 ε 很快冲到几十几百，nm=1 拿到的是 **152.31** 而不是
「个位数」。要把 ε 压到 8 以内，在这个协议下**必须**把 nm 抬到 8。

而 nm=8 时加在批均值梯度上的噪声 Std 是

    nm × max_grad_norm / 期望批大小 = 8 × 1.0 / 40 = 0.2

与实测信号（批均值梯度范数 0.147–0.223）**同量级**。

> **H4 的两半在这里迎面撞上：要 ε ≤ 8 就要把噪声加到和信号一样大。**

这不是实现问题，是数据规模问题。DP-SGD 的效用代价随 `1/√(每客户端样本数)`
恶化，而本仓库每客户端只有 80 行。这也解释了 §12 的 R5 为什么值得登记：
「DP 下模型完全学不动」不是意外，是小客户端的结构性后果。

三条降压路径（`check_dp_budget.py` 失败时会打印）：

| 路径 | 代价 |
|---|---|
| 加大 nm | 效用更差（本备忘的主题） |
| 减步数（减轮数或减 `local_epochs`） | 训练量更少，而坑 12 已经证明训练量是本数据上的绑定约束 |
| 减 q（减小 `batch_size`） | **每 epoch 批次数变多、总步数反而上升**，不一定有用，别凭直觉调 |

## 3. 机制开销与噪声开销必须分开

`nm=0` 那一行只做逐样本裁剪 + Poisson 抽样、**不加噪**，ε 报 `inf`。它不是
DP 臂，是**机制对照组**（plan §7：没有噪声就没有 DP）。

它相对非 DP 同预算差 **+39.2%**，但 p_t=0.0945——**测不出来**。而 nm=1 在它
之上再加 **+81.8%**，8/8 同向、测得很稳。

合起来报成「DP 一共劣化 +153%」会把两件事混成一个数：

- 换批大小（Poisson 让期望批从 64 变 40）+ 逐样本裁剪：+39.2%，测不出来；
- 噪声：在其之上再加 +82%～+186%，测得很稳。

把机制开销算到噪声头上会**高估** DP 的价格；只报机制开销会让读者以为
「DP 很便宜」。两个方向都是错的，所以 `nm=0` 是这一节里最容易被删、
删了最贵的一行。

顺带一条实测：**Opacus 默认 Poisson 抽样，期望批大小 = 行数 × q = 80 × 0.5
= 40，不是 64。** 关掉它只是近似（Opacus 自己的 docstring 就这么写），本仓库
选择保住保证。代价是 DP 路径的 loss 必须按 `x.shape[0]` 加权（批大小逐批不同），
以及 DP 臂不能直接和非 DP 臂比「同一批数据」——后者吃的是满批。

## 4. 三条比百分比更直观的读数

1. **nm=8 比 C1（完全不联邦，0.03446）还差 34.7%。** DP 把模型推到了
   「不如不聚合」的地步。这条比任何相对差都好懂，也直接回答了
   「联邦还有意义吗」——在 ε ≤ 8 的约束下没有。
2. **所有 DP 臂都远差于常数预测器。** 常数预测器（输出中心化后的 1.0）在
   统一测试集 MAE = **0.00350**（n=400），而五档 DP 是 0.016–0.046，
   最差的一档是它的 **12.3 倍**。说明 DP 下模型不是「学得慢」而是**学不动**。
3. **每档都在 100 轮内单调下降、best ≈ final。** 如 nm=8 为
   round1 0.08026 / round100 0.04643 / best 0.04630——没有过训回落，
   曲线是训练不足的形状。所以「再多训会儿会不会好」的答案是否定的：
   瓶颈是每步的噪声，不是步数。

## 5. 一条不能当优点报的附带发现

DP 各档的 seed 波动（11.7%–13.9%）明显小于非 DP 同预算的 **66.7%**。看起来
像「DP 让训练更稳定」，但按 §11.3.5 记下的 FedProx 教训——**稳定性 ≠
正确性**——这只是逐样本裁剪把每样本梯度范数压住的结果，而裁剪同时就是代价的
来源之一。按 §11.3 的「seed 波动 <10%」这一行，FedProx 当年反而是唯一达标
的配置之一，而它是三者中最差的。**这一格只作为现象记录，不进结论。**

## 6. 实现要点

- **会计器每客户端一个，且绝不乘 N。** 联合机制是 N 个机制的乘积，「改变
  客户端 i 的一条记录」只影响客户端 i 自己的更新（其余 N−1 个逐位不变），
  所以 `ε_joint = max_i ε_i`。写成 `N × ε_i` 会让隐私保证凭空紧 23 倍——
  **虚高的 ε 看起来很"严谨"，所以这个错特别难被发现**。
  执行点：`src/flsoh/dp.py::DPTrainer`，`tests/test_dp.py` 钉住
  「每客户端独立且不求和」。
- **会计器必须跨轮存活。** 每轮新建会让 ε 少算 100 倍。
- **DP 时每客户端一个 `build_model` 实例。** Opacus 包装会注册前向钩子，
  同一模块包装 N 次 = N 套钩子。
- **`noise_multiplier=0` 与 `None` 是两件事。** `None` = 完全不开 DP；
  `0.0` = 开机制（裁剪 + Poisson）但不加噪，ε=inf。CLI 用 `is not None`
  判断，防 `--noise-multiplier 0` 被静默换成不开。
- **`importorskip` 必须是测试文件的第一个 import**，`test_dp.py` /
  `test_dp_budget.py` 才能在没装 opacus 的默认 CI job 里干净 skip。

## 7. 复现

```bash
# 先算预算（扫 nm 之前必须做，否则可能三档全都 ε>8）
python scripts/check_dp_budget.py --config configs/dp.toml

# 五档 × 8 seeds
for nm in 0 1 2 4 8; do
  for s in 0 1 2 3 4 5 6 7; do
    python scripts/run_federated.py --config configs/dp.toml \
      --features $F --partition-json results/partition-mvp-k5-iid.json \
      --strategy fedavg --noise-multiplier $nm --seed $s \
      --tag "fedavg__iid__le3__nm${nm}__seed${s}"
  done
done

# 判定与出图
python scripts/summarize_results.py --judge --hetero results/heterogeneity.json
python scripts/make_figure3.py
```

判定段落的完整输出见 `summarize_results.py --judge` 的 `M4 / H4` 一节；
表 2（§10.2 的 `D1@nm=*` 五行）由 `--write-plan` 生成、CI 逐字核对。

## 8. 遗留

- **full.toml 的 privacy 段改成了 `[0, 1, 2, 4, 8]`，但它的 k=2 会让 q 退化到
  1.0。** 跑之前必须重算一次预算（`check_dp_budget.py` 会做这件事），否则扫
  出来的点可能一个都达不到 `dp_epsilon_max`。
- **换个威胁模型能不能救效用，本备忘没有回答。** L3（服务器侧
  `DP-FixedClipping`）保护的是客户端更新而不是单条样本，与 L2 不可混谈；
  要在本协议下把 ε 压到 8 以内且不掉点，需要的不是调参而是**每个客户端更多
  的数据**（把 80 行变成 800 行，噪声 Std 相对信号降 √10 倍）。
